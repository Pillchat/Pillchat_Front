### PDF AI 카드 재검증 — 2026-10-07 00:00 KST 전후

사용자가 다시 로그인한 **기존 탭**에서 `/flashcards`의 실제 카드 13장을 확인한 뒤 카드 만들기로 진입했다. 숨긴 PDF 문제 제작 기능과는 별개로 현재 AI 플래시카드의 PDF 원본 업로드를 테스트했다.

- 파일: `pillchat-integration-20261006.pdf`, PDF 1.4, 1페이지, 1,184바이트. 개인정보 없는 확산·삼투 등의 합성 학습 자료.
- 제목: `연동테스트 1006 PDF`, 유형 CONCEPT, 카드 수 2.
- 프론트 → 실제 백엔드: `POST http://5.223.79.190:8080/api/flashcards/sources`, multipart `file` 및 JSON `metadata`.
- 업로드 실패를 프론트 서버에서 기록한 값:

```text
AI 카드 원본 업로드 실패 {
  status: 401,
  authorizationProvided: true,
  code: 'AUTH_REQUIRED',
  error: 'AUTH_REQUIRED',
  message: '로그인이 필요합니다.'

```

위 로그가 2회 기록됐다. 인증 복구 후 재전송하는 클라이언트 구현과 일치한다. 이는 전체 응답 body 덤프가 아니라 HTTP 상태 및 응답 오류 필드·인증 헤더 존재 여부를 선별한 기록이다. 토큰 값과 파일 내용은 로그에 남기지 않았다.

업로드 실패 직후 **같은 탭에서 카드 목록을 재조회하여 2개 팩·13장과 기존 테스트 카드가 다시 표시됨을 확인**했다. 따라서 단순히 로그인을 하지 않아 실행하지 못한 것이 아니다. 인증 헤더를 전달한 원본 업로드 API가 인증 오류를 반환한다. 헤더가 있다는 사실만으로 서버 내부 원인까지 확정하지는 않는다. 백엔드의 해당 요청 인증 처리 및 multipart/파일 저장 중 오류 로그 확인이 필요하다.

PDF 원본 업로드가 실패했으므로 PDF 추출·AI 카드 생성·초안·저장까지 진행되지 않았다. 이번 재검증에서는 신규 카드가 생성되지 않았고 로그아웃하지 않았다. 테스트 탭은 카드 목록으로 돌아온 로그인 상태로 유지했다.

### 테스트로 남은 데이터와 한계

- 기존 카드 12장은 변경/삭제하지 않았다. 신규 “연동테스트 1006 직접” 팩·카드 1장과 그 카드의 학습 기록이 남았다.

- 모든 학습 기능이 정상 사용 가능하다고 판정하지 않는다. 실패 지점 이후의 AI 초안 수정·저장·문제 채점, 시험 데이터가 필요한 응시·복습은 미검증이다.

## 기존 프론트 변경 내역

- **인증:** 가입 verificationToken과 재설정 resetToken 전달, 412 재인증 안내, 두 fetch 모듈의 refresh 공유, access/refresh 동시 교체, 기존 refresh fallback 제거. 403 일반 요청은 refresh하지 않는다. 네트워크/503 실패는 세션을 지우지 않으며, 오래된 refresh의 성공/실패가 새 로그인 정보를 덮어쓰지 않도록 보호했다. 지원 브라우저에서는 Web Locks로 탭 간 refresh도 직렬화한다.
- **수제·CBT:** 기본 화면을 서버 카탈로그 기반으로 연결했다. 문자열 응시 ID를 URL에 보관하고 서버에서 복구한다. 답안·메모·체크·보기 제외, 답안별 버전, 교시별 버전, 제출·채점·공개 결과, 서버 시간 기준 CBT 휴식/다음 교시를 연결했다. 기존 연습 구현은 `_components/LegacyPractice.tsx`에 보존했으며 `?mode=sample`은 체험임을 표시한다.
- **복습·AI:** 기본 복습 목록을 출처별 서버 cursor 목록으로 전환했다. 시작 응답의 LEARNING/LEGACY_AI 엔진에 따라 분기한다. AI 정답 보기는 서버 REVEAL로 전송하고, 응시 복구 API와 시작 UUID 재시도를 추가했다. 종료 실패를 성공으로 취급해 결과 화면으로 이동하지 않는다. 서버에서 반영하지 않는 AI 주제 힌트 입력은 숨겼다.
- **카드:** 원본 multipart(metadata JSON part 포함) → 팩 → 생성 상태 폴링 → 초안 수정/제외 → 일괄 저장을 연결했다. 생성 ID는 URL로 복구하고 팩·카드 분류도 서버에서 읽는다. 직접 생성/이미지 가림 카드에도 팩을 연결한다. BLIND mask는 width/height로 전송한다.
- **알림:** 서버 목록·미읽음 수·개별/전체 읽음·개별/전체 삭제·더 보기를 연결했다. 전체 처리는 조회한 snapshotSequence 문자열을 사용한다. 계정별 query key로 목록을 분리하고 로컬 push 수신은 서버 목록 갱신을 요청한다. NEW_FOLLOWER와 수신 설정을 추가했다.
- **계정·커뮤니티:** 별도 follow-summary 조회, 팔로우/해제, 프로필 grade 내부 통계, 신고 USER enum, 숫자형 답변 좋아요 수, 오답노트 owner/liked 매핑을 보완했다. 프로필 수정 인증은 공통 Authorization을 사용한다. 공지 목록/상세와 설정·마이페이지 진입을 추가했다.
- **관리자:** SYSTEM 발송, ALL/USERS 구분, UUID 유지와 UTC 예약 시간을 적용했다. 화면의 발송 이력은 서버 Job/status/counts에서 조회한다. 이 작업 중 실제 푸시를 발송하지 않았다.
- **마켓 — 추가분 제거 완료:** 폐기된 기능임을 확인해 이번 구매·다운로드·구매/환불/판매 내역 프록시를 삭제하고, 상세 구매 버튼·편집 파일 유지·버전 및 타입 변경을 원복했다. 구매·판매 내역 화면과 환불 UI는 애초에 만들지 않았다.
- **BFF:** 신규 API의 bearer, 원본 HTTP status/code/body, 204, 문자열, multipart boundary, no-store를 보존한다. 기존 AI·오답노트 proxy의 JSON 오류 파싱도 보완했다.

## 검증

- `npm test`: 33개 통과. 기존 테스트 13개와 새 계약 테스트 20개.
- `npm run build`: 최종 프로덕션 빌드 및 타입 검사 통과.
- 계약 테스트는 클라이언트/실제 Next route 코드를 실행하고 백엔드 응답을 대체한다. 실제 MySQL/Redis 또는 SMTP/S3/AI/푸시 종단 검증이 아니다.
- 테스트 내용: 동시 refresh 1회, 탭/계정 경쟁 보호, 임시 오류 보존, 인증 경로 refresh 제외, 401 단일 재시도 및 body 유지, 403/status/code, 빈 응답/문자열/숫자, 인증 증명 전달, 큰 문자열 ID, 409 버전 충돌, 동일 UUID 재전송, multipart, AI action/복구 경로, 알림 snapshotSequence, 관리자 audience, BLIND mask, 오답노트 flags.
- 실제 배포 서버: 공개 OpenAPI 조회 성공. 로컬 프로덕션 BFF의 무인증 학습/알림 요청은 403을 유지했다.
- 브라우저: 기존 질문 목록 및 질문 상세의 실제 서버 데이터 표시를 확인했으나 **폐기된 기능이므로 현재 제품의 검증 성과에서 제외한다.** 해당 화면의 콘솔 오류는 없었다. 신규 CBT는 미배포 API 오류 안내를 표시했으며 카드 생성 화면도 렌더링을 확인했다. 신규 응시/카드/알림 정상 흐름의 브라우저 E2E 통과로 간주하지 않는다.

## 후속 연동에 필요한 것

1. 배포 주소·최신 명세 일치와 로그인 세션은 확인했다. 재테스트에서 확인된 파일 업로드·AI 생성·알림 설정 실패 해결 및 공개 수제·CBT 데이터가 필요하다.
2. 새 환경에서 가입·재설정·로그아웃, 응시 새로고침 복구·409·시간 만료, 카드 업로드/생성/저장, 알림 cutoff 및 계정 전환의 실제 E2E 검증.
3. 네이티브 푸시 messageId 탭 콜백은 SDK/실기기 이벤트 확인이 필요하다. 서버 `by-message` 프록시는 준비했지만 실제 수신·탭은 미검증이다.
4. 저장된 카드 수정·순서 변경은 백엔드 계약을 추가로 확정해야 한다. 이번 작업에서 없는 API를 만들어 호출하지 않았다.
5. 관리자 이력 상세/수신자별 재발송은 백엔드 문서에 있지만 UI는 추가하지 않았다. 운영상 필요 여부를 확인하기 전 추가 개발 과제로 확정하지 않는다. 신규 게시판·익명 댓글도 제품 범위가 확인되지 않았고 UI를 추가하지 않았다. 폐기된 질문/답변 및 마켓 기능은 후속 개발 대상에서 제외한다.

홈·아카이브 재설계, 응원방·접속자 수 연결은 수행하지 않았다.
