## 수정한 문제

### 1. 휴대폰 가로에서 CBT 계산기 팝업이 화면 밖으로 잘림

- 재현: 844×390에서 CBT 풀이 → 하단 계산기 열기.
- 관찰: 팝업 상단 제목·닫기 버튼과 아래쪽 계산 버튼이 화면 밖으로 나간다. 닫기 버튼이 보이지 않아 접근 테스트가 실패한다.
- 코드 위치: `components/learning/practice/CbtPresentation.tsx:1129`, `:1135`.
- 원인으로 확인한 구조: 화면 중앙에 고정된 팝업에 화면 높이 기준 최대 높이와 내부 세로 스크롤이 없다. 가로 폭이 넓어지면 계산기 키는 `sm:h-14`로 커진다.
- 수정: 팝업 최대 높이를 `100dvh - 2.5rem`으로 제한하고, 제목·닫기 영역은 고정한 채 본문을 세로 스크롤하도록 바꿨다. 마지막 계산 키까지 사용한 뒤 닫기 버튼에 접근할 수 있음을 검증했다. 같은 Dialog를 쓰는 제출·나가기 팝업도 짧은 화면에서 통과했다.

### 2. 좁은 CBT 헤더에서 ‘시험 나가기’ 버튼이 가려짐

- 재현: 시간 제한 없는 CBT 연습을 320·360·390px 폭으로 열기.
- 관찰: 문제 수·1문제/2문제 배치·도움말·‘시간 제한 없음’ 표시가 한 줄을 차지하며 왼쪽 나가기 화살표가 가려진다. 320px에서는 배치 버튼 글자도 여러 줄로 꺾인다. 동일 검사의 412px 폭은 통과했다.
- 코드 위치: `components/learning/practice/CbtPractice.tsx:595`.
- 원인으로 확인한 구조: 첫 열이 `minmax(0,1fr)`이고 나머지 두 열이 `auto`여서 오른쪽 컨트롤의 폭에 밀린다. 나가기 버튼 자체는 40px이지만 그 공간이 첫 열에 보장되지 않는다.
- 수정: 첫 열의 최소 너비를 40px로 보장했다. 480px 미만에서는 하단과 중복되는 문제 수 표시와 배치 버튼의 장식 아이콘을 숨기고, 버튼·시간 표시의 간격을 줄였다. 1문제/2문제 전환과 도움말·시간 표시는 유지한다. 시간 제한 유무별 320·360·390·412px에서 버튼 접근과 실제 조작을 검증했다.

수정은 기존 웹의 반응형 화면에 한정했다. 자체 Expo 앱·모노레포 POC는 시작하지 않았다.

## 테스트 정비

- 기존 테스트의 오래된 버튼명 `결과 확인`·`복습하기`를 현재 화면의 `결과 보기`·`이번 세트 오답 해설`에 맞췄다.
- 현재 헤더 구조에 맞춰 뒤로가기와 오른쪽 슬롯 사이의 제목 영역을 검사한다. SSR hydration 전에 DOM을 바꾸던 테스트의 오탐도 제거했다.
- fixture와 공통 검사를 분리하고, 의도된 가로 스크롤 영역은 페이지 넘침과 구분했다. 긴 콘텐츠는 스크롤한 뒤 접근 가능 여부를 확인한다.
- `--env screenAudit=true`를 지정하면 스크린샷이 긴 태블릿 viewport에서 잘리지 않도록 테스트 브라우저 창을 확장한다.

## 실기기 검증 전까지 남는 항목

1. 로컬 화면 수정과 브라우저 재검증은 완료. 운영 반영 여부와 실제 사용하는 웹 버전을 확인.
2. 새 iPad 지원 빌드를 실제 iPad에 설치해 iPhone 호환 창이 아닌 앱에 배정된 전체 공간을 쓰는지 확인.
3. 실제 iPhone·iPad·갤럭시 폰·탭에서 브라우저와 설치 앱 비교. 지원할 OS·모델·화면 모드 기록.
4. 실제 계정 로그인·앱 복귀, CBT 답안 저장·제출·타이머, 글쓰기·파일 선택·등록 확인.
5. OS 키보드·터치·safe area·시스템 뒤로가기·회전·앱 재개 확인. 맥북 viewport 변경으로 대체할 수 없다.

사용자와 정한 순서는 **화면 문제 해결·실기기 확인 후 자체 앱 POC**다. 이 문서의 통과 숫자를 전체 호환성 ‘100% 완료’로 해석하지 않는다.
