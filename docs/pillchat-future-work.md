## 2. 전체 구현 순서 추천

1. `AppShell`, `BottomNav`, 480px 컨테이너, safe-area 레이아웃을 먼저 정리한다.
2. 라우트 네이밍 결정을 반영해 하단 5탭 네비게이션을 만든다.
3. 홈 `/`에 D-Day, 추천 콘텐츠, 빠른 진입을 붙인다.
4. 학습 티저 `/learn`을 구현한다.
5. 게시판 허브 `/boards`와 꿀팁/자유/후기 목록 구조를 확정한다.
6. 게시글 상세 공통 상단바, 댓글/대댓글, 액션바를 공통화한다.
7. 자료 마켓 목록/상세/업로드를 구현한다.
8. 응원방 `/cheer`를 프론트 MVP로 만든 뒤 실시간 백엔드를 붙인다.
9. 프로필/팔로우/뱃지 상세을 정리한다.
10. SEO, 접근성, 하이드레이션, IME, 테스트를 릴리스 전 점검한다.

## 16. 작업 시 주의할 점

- 명세의 신규 라우트와 현재 코드의 기존 라우트가 다르므로, 구현 전에 `DEC-001`, `DEC-002`를 먼저 해결한다.
- 새 화면은 가능한 한 `AppShell`과 공통 하단바를 쓰도록 만든다.
- 특정 route에서만 쓰는 컴포넌트는 `app/<route>/_components`에 둔다.
- 여러 route에서 공유하는 작은 UI만 `components/atoms` 또는 `components/molecules`로 올린다.
- URL로 직접 참조하는 SVG는 `public/icons`, `public/illustrations`, `public/brand` 중 역할에 맞게 정리한다.
- 결제, 실시간 채팅, 영상 스트리밍은 외부 시스템 의존이 크므로 UI MVP와 실제 연동을 분리해서 진행한다.
